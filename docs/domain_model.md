1. Бизнес-контекст

Мы строим игровую платформу-трекер (своего рода облегченный аналог Steam). Это система, где пользователи могут просматривать каталог тайтлов, добавлять их в свою личную библиотеку, а платформа будет отслеживать их игровые сессии (наигранные часы) и заработанные очки, формируя глобальные рейтинги игроков.



2\. Основные сценарии (Use cases)

Управление аккаунтом: Регистрация и авторизация пользователя.

Работа с библиотекой: Просмотр общего каталога (например, поиск масштабных сюжетных RPG или инди-игр) и добавление игры в личную библиотеку.

Трекинг активности: Система фиксирует старт и завершение игровой сессии пользователя, подсчитывая время онлайн.

Начисление очков: Во время сессии пользователю могут начисляться очки (score) за достижения.

Статистика и рейтинги: Запрос статистики конкретного игрока (сколько часов наиграно) и вывод глобального лидерборда по конкретной игре.





3\. Основные сущности

User (Пользователь): ID, никнейм, email, дата регистрации.

Game (Игра): ID, название, описание, жанр, разработчик.

LibraryRecord (Запись библиотеки): Связка "Пользователь-Игра" (ID пользователя, ID игры, дата добавления).

Session (Игровая сессия): ID сессии, ID пользователя, ID игры, время начала, время завершения, статус (активна/завершена).

Score (Очки/Результат): ID пользователя, ID игры, количество очков, дата получения.



4\. Связи между сущностями

Один User может иметь много LibraryRecord (игр в библиотеке) — связь 1:M.

Одна Game может находиться во многих LibraryRecord — связь 1:M.

Один User может сгенерировать множество Session — связь 1:M.

Каждая Session привязана строго к одной Game — связь 1:1 (со стороны сессии).



5\. Бизнес-правила и ограничения

Пользователь не может запустить сессию для игры, которой нет в его LibraryRecord.

У одного пользователя не может быть двух активных (незавершенных) сессий одновременно.

Время завершения сессии не может быть меньше или равно времени начала.

Очки (Score) могут начисляться только в рамках существующей игры в системе.
